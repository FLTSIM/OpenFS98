## Intent

**Problem:**
- Two hand-written test gauges take their `.data` from the CD at build time:
  - `737-400.WARNING_ENUNCIATORS.GAU`: `src/gauges/warning.c`, from `orig/Gauges/737WARNG.GAU`, 0xfc bytes, 14 pointers.
  - `CESSNA_182.SUCTION.GAU`: `src/gauges/suction.c`, from `orig/Gauges/CESSSUC.GAU`, 0x298 bytes, 19 pointers.
- `tools/gen_warning_data.py`, with `extract()` shared by `tools/gen_suction_data.py`, writes into `bin/gauges-diff/`:
  - `<name>_data.inc`, the image as hex bytes with its pointer slots zeroed;
  - `<name>_pointers.inc`, one C assignment per relocated slot;
  - `<name>.res`, the bitmaps.
- The C includes the two `.inc` files through `-Ibin/gauges-diff`.
- The lines that build the gauges are repeated in six targets (`cmake/targets.cmake`): `gaugesdiff-run`, `suctiondiff-run`, `gauges-panels-run`, `gauges-game-run`, `suction-game-run` (:531) and `suction-breaks` (:1996). `tools/gauges_breaks.py:86` builds them too.
- Neither gauge has a manifest row.

**Approach:**
- **Typed image.**
  - Commit `src/gauges/warning_data.inc` and `suction_data.inc` as typed C in `src/host/host_image.inc`'s style:
    - `AT(off)` at the `.data` offset, with `U8`/`U16`/`U32` and `STRn` values;
    - zero runs of 16 bytes or more left out;
    - the pointer slots zero;
    - regions named from `docs/modules/gauges.md` and the C that reads them (the element and bitmap records, ImportTable +0xc8/+0x260, Linkage +0xd8/+0x270), and the rest marked "meaning not yet known".
  - A scratch script outside the repo writes them. They must equal the generated bytes.
  - A quoted include finds them first, before the `bin/` copies.
- **Pointer lists.**
  - Commit `src/gauges/warning_pointers.inc` and `suction_pointers.inc` as `GAUGE_DATA(off, target)` and `GAUGE_CODE(off, rva, routine)` lines.
  - Each gauge's C defines the two macros so that they install exactly the assignments the generated file makes today, in the same order.
  - `check_data_image.py`'s `ptrs=` parser accepts the two forms. Today `ptrs=` is refused when retail's ImportTable offset is not 0 (`check_data_image.py:686`), and these are at +0xc8 and +0x260. So for `GAUGE_*` lists only, that refusal does not apply, and the image is still found from the ImportTable export:
    - **Coordinates:** `off` is the slot's offset from `.data`'s start. `GAUGE_DATA`'s `target` is a `.data` offset (the slot holds base + `.data` RVA + target). `GAUGE_CODE`'s `rva` is a code RVA (the slot holds base + rva). For example, warning has `GAUGE_DATA(0x28, 0xc0)` and `GAUGE_CODE(0x2c, 0x10b0, warning_failures)`.
    - The target-base dispatch (`check_data_image.py:463`) gets the two forms.
    - A `GAUGE_CODE` row is parsed as a three-field entry, with `routine` discarded; four fields mean MULTIP's entries.
    - Each slot and target must equal retail's relocated slot and target. `routine` is not checked; the whole-binary gate and the queued difftests cover it.
- **Resources only.** `gen_warning_data.py` and `gen_suction_data.py` keep only the `.res` and every layout assert: the base, exports, data size, imports, pointer count, bitmap layout and suction's clamp bounds. Both move from `gen:` to `resource:`.
- **One build target.**
  - A new build-only target, `test-gauges`, holds the six build lines once, plus a `--hash` line per gauge.
  - The six targets `DEPEND` on it instead of repeating the lines, keeping their other dependencies and run commands, and `data-images` depends on it too.
  - Two manifest rows are added with `UPDATE=1`: `WARNING Gauges/737WARNG.GAU bin/gauges-diff/737-400.WARNING_ENUNCIATORS.GAU ptrs=…` and `SUCTION Gauges/CESSSUC.GAU bin/gauges-diff/CESSNA_182.SUCTION.GAU ptrs=…`.

**Gate:**
- The two `.GAU` files must be identical to their pre-slice builds after `i686-w64-mingw32-strip` and `peh2.py`. The copies are in the scratchpad's `pre18a/`:
  - warning: 666f85f5d1e6cc0a stripped, 824586c5255cca6f unstripped;
  - suction: 0d1c95d60533f65e stripped, cdc50a3275050c61 unstripped.
- If the unstripped hashes still match, say so.
- `data-images` must pass with 30 rows.
- If code or layout changes, report it and stop.

**Queued with the held-back runs:** `gaugesdiff-run`, `suctiondiff-run`, `gauges-panels-run`, `gauges-game-run`, `suction-game-run`, `suction-breaks` and `gauges_breaks.py` (warning).
