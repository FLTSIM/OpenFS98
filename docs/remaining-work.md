# Remaining work

What is still retail, what is not yet decompiled, and what is left before a native build. Every
binary now has a replacement: the 27 simulator modules in `Modules\` are in `MODULES`;
`English\` World, Alerts, Help, Sim, Views, Flights, MP_DIALOG and Options are in
`ENGLISH_MODULES`; SIMSUI is in `SHARED_MODULES`; SIM1, the gauges and the MDLs have their own
targets. `make install` puts them all in the game. Sizes are `.text` from the reference CD.
Differences and gaps in the finished modules are in [open-differences.md](open-differences.md).
Results updated through 2026-11-14; individual rows retain their acceptance dates.

## Lifted code, all removed (2026-11-14)

Found 2026-11-07: four replacements made by other agents were **lifted**: a Python generator read
retail's instructions and wrote C that emulated them one by one, with the x86 registers and flags
in a struct and the jumps as `goto`s (`f->eax = mdl_read(f, ...); if (f->flags & 0x40) goto
label_437f;`), generated into `bin/` at build time. It matched retail but was not a decompilation:
nobody could read or change it, and it could not leave x86. Each was decompiled by the usual method
(hand-written C, a differential harness, deliberate breaks), with the lifted build kept as a second
oracle until the hand-written one had replaced it. On 2026-11-14 the lifts were deleted, oracles
included: the generators (`tools/gen_sim1_lift.py`, `tools/gen_host_runtime.py`, the lowering in
`tools/gen_gauges.py` and `tools/gen_mdl_crash.py`), their runtime headers and shims, the lifted
builds and the suites that tested only them. What the hand-written code still needs from those
generators is kept as plain surveys (no code emitted): the gauges' data images and harness
metadata (`tools/gen_gauges.py`), the crash models' CHAIN callback (`tools/gen_mdl_crash.py`) and
the executable's routine list (`tools/host_rt_survey.py`, for `tools/gen_host_rt_tables.py`);
each was checked to produce byte-identical output. G3D's mesh compiler, which x86 builds took as
retail's instructions (`src/g3d/g3d_mesh.S`, generated by `tools/gen_g3d_mesh.py`), is now
`src/g3d/g3d_mesh.c` everywhere, and `g3dmeshdiff` runs it against retail's own `G3D.DLL`.

### Routines the services share with the runtime

Retail's services and its runtime share 45 routines: the display settings' device list and
reader, DirectDraw opened and released, full screen in a window, the module list, the modeless
dialogs, the paused look, sound's start, the frames' stacking, a message to every window and the
game's message hook. Until 2026-11-14 `src/host/host.c` and `src/host/runtime/` each had its own
copy (28 of them listed here; 17 more had not been noticed). Now there is one: the runtime's, in
five files (`host_rt_ddraw.c`, `host_rt_config.c`, `host_rt_modules.c`, `host_rt_display.c`,
`host_rt_common.c`), and `host.c` calls them. A build of the services without the runtime
(`HOST.DLL` for `hostdiff` and its breaks) compiles those five with
`HOST_RT_STANDALONE` (`host_rt.h`), where an import goes through that build's own import table, so
`hostdiff`'s hooks still see it ([host.md](modules/host.md#the-runtime-decompiled)). Both
harnesses run the one copy: `hostrtdiff` directly, `hostdiff` through the services.

## The gauges

All 120 reference-CD modules are hand-written C (see above) over generated data images and
bitmap resources. The shared build, install and revert targets include them. Standalone
verification covers every exposed callback, all x87 precision/rounding modes,
full data/resource comparisons and forced relocation; PANELS and real-game
checks exercise the collection together. See [gauges.md](modules/gauges.md).
Their current 32-bit ABI still needs adaptation with the rest of the native port.

## SIM1 and the MDLs

Both are ordinary module DLLs with their own Linkage, loaded by ACONTAIN through host
`+0x26c` rather than from `Modules\` ([acontain.md](modules/acontain.md)), so the module
harness patterns apply to them. SIM1 has been verified against the reference
CD and copied to `orig/Sim/` (2026-11-06). All eleven MDLs, including
`C182/MODEL.RG`, have been byte-compared with their mapped CD files and copied
to `orig/Aircraft/` (2026-11-06).

- **`SIM1.sim`** (base `0x22000000`, `.text` 78,216, `.data` 17,400): imports only KERNEL32
  and MSVCRT, and links to modules 1, 2, 3, 4, 10, 16, 20, 23, 32 and 39. It calls host
  `+0x21c` 77 times and reads and writes GLOBAL widely, like DYNAMIC. As large as SIMSUI and
  in every flight. It is now implemented and installed: six services and the
  state lifecycle have isolated comparisons; the real AIR decoder, aircraft
  setup and simulation callbacks add standalone and game acceptance. All 74
  scripted flights match numeric state and frames. Native-platform ABI and FP
  work remains; see [SIM1](modules/sim1.md).
- **The `.MDL`s**: eight normal models (`.text` 678–982 bytes) and three crash
  models (9,110–9,894 bytes), mostly `.data`. Shared Linkage scaffolding wraps
  distinct header update callbacks; crash models also register with CHAIN.
  All eleven now have C implementations and standalone differential verification;
  see [MDL verification](modules/mdl.md) for game acceptance and remaining limits.
