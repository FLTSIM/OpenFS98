# Retail bugs kept on purpose

The reimplementation matches retail, bugs included, because differential testing
against retail is how it is verified ([method.md](method.md)). These are the bugs we know
we are reproducing. **They are to be fixed at porting time**, once comparison with retail
is no longer the test; until then each stays matched, and a fix before then breaks the
comparison that would catch everything else.

Each one is marked in the code with `RETAIL BUG (<kind>): <id>` in a comment, kind `kept`,
`kept, suspected` or `fixed, not kept` as the Id cell says, so
`grep -rn "RETAIL BUG" src/` lists them all. An entry says what goes wrong, when it can
happen, what the fix should be, and where the code is. An id with `(no longer applies)` has
no marker and a sentence saying why.

`python3 tools/check_retail_bugs.py` checks the markers and this register against each other
both ways. The ids still unmarked are in `tools/retail_bugs_unmarked.txt`, which may only
shrink (Story 1.5, in progress): the sections for MAIN.DLL, Flights.DLL, Options.DLL and
Gauges are marked and checked against the code; the others carry the module doc's account
and the code has its own comments (often `QUIRK` or "retail") where it reproduces them.

New bugs found while reimplementing go here as well as in the module's own doc.

Entries marked *(suspected)* are a reading of the disassembly no game run has shown;
*(fixed, not kept)* were fixed on purpose because their only outcome is a crash. Faults that
depend on stack garbage, unchecked lengths or a wild program are listed even where the
harness keeps clear of them: the port should not inherit them.
